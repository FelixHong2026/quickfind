## 四、常见提问应答（提前背下来）

### Q: 为什么不用 Everything？

> Everything 快得多，而且有实时索引 —— 它读 NTFS MFT，我是遍历文件系统。如果你要极致速度和实时性，**用 Everything**。
> QuickFind 想做的是另一件事：**和文件管理器打通**。右键直接在 DOpus 里定位并选中，这个 Everything 做不到；加上 1200 行纯 Python 你随时能改。

### Q: 和 Listary 比呢？

> Listary 更成熟，有文件对话框跳转（那个我没做，也不打算近期做）。
> 我的取舍是：**去掉对话框注入这类侵入式功能**，只保留"热键 → 秒搜 → 在文件管理器里定位"这条主链路，然后把它做干净、做成能读能改的开源项目。

### Q: 索引 47 万文件要多久？

> 我这台机器（47 万条目）约 **5 秒**，搜索 **17-56 ms**。你的机器取决于文件量和磁盘类型。索引缓存在 SQLite，之后启动是秒开。

### Q: 为什么 Windows 说"已保护你的电脑"？

> exe 没做代码签名（个人项目，证书费用不划算）。源码全在仓库里，你可以自己 `python src\quickfind.py` 跑，或者自己 build。

### Q: 杀毒软件报毒？

> PyInstaller 单文件打包被启发式引擎误报是常见现象。同上 —— 建议从源码跑，或者用 `build\build.ps1` 自己打包。

### Q: 会支持 Linux / macOS 吗？

> 短期不会。用到了大量 Windows 专有 API（`RegisterHotKey`、`GetAsyncKeyState`、`explorer /select`），换平台要重写核心。

### Q: 能加模糊匹配 / 拼音吗？

> 在计划里。当前只做子串匹配，所以 `qfk` 匹配不到 `quickfind.py`。拼音首字母也是缺的 —— 欢迎 PR。

### Q: 为什么用 Python 而不是 C++/Rust？

> 为了"可读可改"。1200 行、零第三方依赖，一个下午能读完。速度上做了两件事弥补：索引写入 SQLite 缓存、搜索用 C 级列表推导 + 预存小写路径。
