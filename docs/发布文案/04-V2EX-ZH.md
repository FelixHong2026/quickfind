## 正文（直接复制）

```text
用 Listary 很多年，最常用的其实只有一件事：搜到文件，然后跳过去。

但有个环节一直不舒服——搜到了，还得在资源管理器里一层层点进去对准那个文件。
我平时用 Directory Opus，就想要"右键一下，DOpus 直接停在那儿，文件已经选中"。

找不到现成的，就自己写了一个。

## 它做什么

- 全局热键唤起（默认 Ctrl+Shift+/，可以随便改：数字、字母、F 键、符号都支持）
- 打字即出结果（同时匹配文件名和完整路径，文件夹也能搜到）
- **右键 → 在 Directory Opus 中定位** → DOpus 跳到所在目录，并且**已经选中那个文件**
- 没装 DOpus 就自动回退到资源管理器
- 5 套皮肤、中英双语（跟随系统语言）、✕ 行为可配置（隐藏到任务栏 / 直接退出）、开机自启开关
- 索引自动跳过 AppData / node_modules / 虚拟环境 / 云占位文件 / 网络盘

## 技术上的几点

索引方式：`os.scandir` 遍历 → SQLite 缓存。**没有**读 NTFS MFT，所以不需要服务、
不需要管理员权限、不需要驱动 —— 代价是首次建索引慢一点（我这台机器 47 万条目约 5 秒）。

搜索：预先存好小写路径，用 C 级列表推导过滤。47 万条目 **17-56 ms**。

热键捕获踩了两个坑：

1. Tk 对 Shift 组合键上报的 keysym 是错的（`Shift+/` 是 `question`、`Shift+0` 是
   `parenright`），靠字符映射会静默注册成错误的键
2. 有些组合（实测 `Ctrl+Shift+0`）**根本不会作为 KeyPress 事件到达窗口**

最后的解法是彻底不用按键事件：每 25 ms 轮询 `GetAsyncKeyState`，扫 90 多个候选
虚拟键码，修饰键也用它实时读。这样既不漏键，也不会凭空多出 Alt。

## 我不打算做的事

- **不做文件对话框注入**（Listary 的 QuickSwitch）。要往别的进程里注入，我不愿意承担
  那个不稳定性和风险。
- 不去和大厂比速度。Everything 读 MFT，实时索引，它比我快得多，**要比速度请直接用
  Everything**。
- 短期不做模糊匹配和拼音首字母（在计划里，但优先级低于稳定性）。

## 现状

**Beta v0.9.0**。索引是快照（新文件要等下次重建），只做子串匹配，
exe 没有代码签名（所以 SmartScreen 会警告，介意的话可以直接 `python src\quickfind.py` 跑）。

- 仓库（MIT）：https://github.com/FelixHong2026/quickfind
- 直接下载：https://github.com/FelixHong2026/quickfind/releases/latest
- README 里有截图

1,200 行、零第三方依赖，一个下午能读完。有想要的功能或者发现问题都欢迎提 issue。

顺带一问：**有没有 DOpus 老手知道比 `dopusrt /cmd Go` + `/cmd Select` 更合适的命令？**
这块是我最没把握的地方。
```

### 可能被问到的两个问题，应答

**"和 Listary 比怎么样？"**
> Listary 更成熟，而且有对话框跳转。我的取舍是把侵入性的功能全砍掉，只留
> "热键 → 秒搜 → 在文件管理器里定位"这条主链路，然后把代码做成能读能改的开源项目。
> 如果你就要对话框跳转，那还是用 Listary。

**"为什么不用 Everything + 快捷键？"**
> Everything 更快，我一直也装着。但它解决的是"找到"，我要的是"到那儿"——
> 右键直接在 DOpus 里定位并选中，这个我在 Everything 上没找到顺手的做法。
